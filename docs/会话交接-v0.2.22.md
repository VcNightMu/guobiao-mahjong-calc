## 6. 环境与工具链事实（踩过的坑）

1. **工具链**：`rust-toolchain.toml` 仅在**进程 CWD 位于仓库内**时生效；否则 rustup 用默认 MSVC ⇒ `linker 'link.exe' not found`。
2. **feature**：测试/构建一律 `--no-default-features`；GUI 需 `--features gui` **且**把 WinLibs mingw64 的 `bin` 前置到 `PATH`（默认 `cargo build` 不拉 eframe）。
3. **门禁脚本必须纯 ASCII**：`>127 = 0`、`CR = 0`（PS 5.1 按 ANSI 读无 BOM 文件，中文会破坏字符串）⇒ 中文走 Base64 或**数据外置 TSV**（修订 11）。
4. **证据纪律**：committed 证据**文件名不得以 `_` 开头**（`_*.png` / `_*.txt` 全仓忽略）⇒ 每次用 `git check-ignore -v` 自证；**陈旧二进制 = 假证据**（判定 `exe mtime ≥ src mtime`；本会话 T82 又踩了一次 release 未重建导致计数不自洽）；**报 0 之前先证明能报 1**。
5. **已知陷阱**：`Measure-Object -Line` **只数非空行**（行数口径统一用 `[System.IO.File]::ReadAllLines().Count`，修订 12）；`$ErrorActionPreference='Stop'` + 原生 stderr ⇒ `NativeCommandError` 与 `exit -999`（修订 13）；debug 二进制 sha 含源码路径 ⇒ **sha 不等 ≠ 行为变化**（修订 14）；`.NET` 静态 API 按**进程 CWD** 解析相对路径（相对路径校验 UTF-8 会误报）。
6. **修订 18（本会话新增）**：并发成员**不得共用 `target/`** —— 会报 `failed to remove file … 拒绝访问 (os error 5)`，并让门禁出现瞬态 `PASS 6 / FAIL 2`（第 1 步 exit 101、第 2 步 `current names = 0`），**极易误判为代码坏了**；正确做法：各自 `--target-dir %TEMP%\<task>`，见到 `os error 5` 先查是否有他人在构建，**不得删/覆盖他人产物**；门禁瞬态失败**等 20 s 重试一次**再判。
7. **测试耗时**：`--test plan` 约 **10.6–12.4 s**；`cargo test --no-default-features` 约 1 分钟级；`cargo test --test plan_invariants` 约 **6.7 s**。
