## R3 专项：`×` 删除副露（**真人点击**）

> **背景**：R3 = GUI「×」删除副露的清理缺口（`src/bin/gbmj_gui.rs` 的 `remove_meld`，T31 已修：删副露 + 清 `pending_chi` + 清 `hint` + 置 `dirty`，**按半复位裁定不复位 `mode`**）。
> 现状证据：**代码同路径证明** + `GBMJ_DEMO=23` 的**窗口级读图双证**（L3 盲转写 + 像素分簇，见报告 §二十六/§三十二）。**唯一残余缺口 = 从未有真人真实鼠标点击**。

### 前置（一次性，约 1 分钟）
1. **构建（必须带 `--features gui`）**：`Cargo.toml` 现为 `default = []`，**不带** `--features gui` 会报 `requires the features: 'gui'` 并 **exit 101**。
   ```powershell
   cd F:\AllCodes\guobiao-mahjong-calc
   $env:PATH = 'C:\Users\Administrator\AppData\Local\Microsoft\WinGet\Packages\BrechtSanders.WinLibs.POSIX.UCRT_Microsoft.Winget.Source_8wekyb3d8bbwe\mingw64\bin;' + $env:PATH
   cargo build --release --bin gbmj-gui --features gui
   ```
   （PATH 前置 = 64 位 MinGW-w64 工具链；缺它时构建可能因 32 位 `dlltool` 失败——**已实测的环境坑**，非代码缺陷。）
2. **新鲜度校核（必做，否则截图/结论视为伪证据）**：`gbmj-gui.exe` 的 mtime **必须 ≥** `src/bin/gbmj_gui.rs` 的 mtime。
   ```powershell
   (Get-Item .\target\release\gbmj-gui.exe).LastWriteTime; (Get-Item .\src\bin\gbmj_gui.rs).LastWriteTime
   ```
3. **启动**：`$env:GBMJ_DEMO=2; .\target\release\gbmj-gui.exe`
   （用 `GBMJ_DEMO=2` 而非 `23`：**`23` 在夹具内部已经调用了 `remove_meld`**，留给人工的是"删完之后"的状态，**没有 `×` 可点**；`2` 的手牌=7 张 + 2 组副露，正好留出 `×` 给人点。）

### 步骤（每步一句；**点哪里**按界面元素文字描述）
> **起点**：`GBMJ_DEMO=2` 启动后 = 手牌区 7 张、副露区 2 组（`碰 3筒×3`、`吃 1条2条3条`）、模式未选中。

| # | **前置状态** | 点哪里 | 应看到什么 |
|---|---|---|---|
| 1 | 模式未选中 | 点副露区的 **【吃】** 按钮（**上方模式行**） | 【吃】按钮**高亮**（进入吃模式） |
| 2 | 模式 = 【吃】 | 在牌库点 **`1万`** 一张 | 副露区下方出现进度行 **`吃：1万（再点 2 张）`**（`pending_chi` 非空） |
| 3 | **仍须是模式 = 【吃】**（未切过模式） | 点**副露列表里** `碰 3筒×3` **那一行右侧的 `×` 小按钮** —— **⚠️ 不要点上方模式行的【碰】**（两处文字相同、位置不同） | 该副露**消失**（副露区只剩 `吃 1条2条3条`） |
| 4 | 同步骤 3 | 看副露区下方 | **进度行 `吃：…（再点 N 张）` 消失**（`pending_chi` 已清） |

> **⚠️ 分支说明（必读；用户实测走的是 B 分支）**
> - **A 分支**：步骤 1→2→3 **中途不切换模式** ⇒ 步骤 6 才可期待「**【吃】仍高亮**」。
> - **B 分支**（**用户实际走法，已确认可接受**）：若在步骤 3 之前**点过任一模式按钮**（例如【碰】）⇒ `pending_chi` 会在**切模式那一刻**被清空（`src/bin/gbmj_gui.rs` **L381-385** 的 `self.pending_chi.clear();`）⇒ 之后点 `×`：副露消失 + **本就无进度行** + 无提示行，**且不应期待【吃】高亮**（此时高亮的是最后点击的那个模式按钮）。**用户原话「吃已经被覆盖掉了」即指此设计行为** ✅
> - **我方原清单的错误**：曾把「【吃】仍高亮」写成**无条件**预期，未写明「仍在吃模式」这一前置 ⇒ **预期文本有误**（详见 `docs/测试评估报告.md` §三十六）⚠️
