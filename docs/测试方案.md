## 3. R-01 判定谓词（v2.3 · 测试方案确认版）

### 3.0 计分口径的三条硬前提

1. **四栏拆分**：`base` = 该和牌张分解下的**牌型番合计**（不含和法番）。门清：`N=base+2`、`T=base+4`、`L=base+6`、`TL=base+8`；非门清（`base>0`）：`N=base`、`T=base+1`、`L=base+4`、`TL=base+5`。
2. **无番和判定门 = `total == 0`，`total = base + extra`（extra 含和法番）**，且**只在 `mode == Normal`**。
   > **来源：Lead 读码**（`src/fans.rs:1004-1032`）。**非 L3 产出。**
   > 推论：绝张路径 `total = 4 ≠ 0` ⇒ **无番和永不适用于绝张** ⇒ `L` **不可能等于 12**。
3. **自摸路径不授予无番和**（`mode != Normal` 直接排除）⇒ 非门清 `base=0` 时 **`T = base + 自摸1 = 1`**。
   > **来源：Lead 实测**（`78s 东东 --chi 234m --pon 5p --pon 6s` 的 `9条` 行自摸栏 = 1）。
   > **据此关闭 `U-13`**：`base` 在 `T/L/TL` 三栏均取**真实值 0**（`src/fans.rs:1025` 在 extra 并入前求和；无番和的 `total=8` 只写在 `Normal` 分支内），**该列不可能为 9**。**v2.0 的 `T=9` 推导已废弃**（错误原因：把仅点和授予的 +8 横移进了自摸栏再 +1）。

### 3.1 定义：两个世界 + 三态标注

对**结构听牌张** `t`，`concealed` = 未含和牌张的暗牌（`13 − 3n` 张）：

```
g_last(t) ⇔ (concealed[t] == 0)        ← 假设，不是事实（用户裁决）
```

**关键语义（升级 A）**：`g_last=true` 表示「**按绝张算给你看**」，**不否定非绝张世界**。因此：

```
非绝张世界可和(t) ⇔ N(t) ≥ 8 ∨ T(t) ≥ 8          （N/T 恒适用）
绝张世界可和(t)   ⇔ g_last(t) ∧ ( L(t) ≥ 8 ∨ TL(t) ≥ 8 )
可和(t)           ⇔ 非绝张世界可和 ∨ 绝张世界可和

三态（逐张 t）：
  「可和」                 ⇔ 非绝张世界可和 ∧ ( ¬g_last ∨ 绝张世界可和 )
  「条件可和（仅非绝张）」 ⇔ g_last ∧ 非绝张世界可和 ∧ ¬绝张世界可和
  「不可和」               ⇔ ¬非绝张世界可和 ∧ ( ¬g_last ∨ ¬绝张世界可和 )
```

**三护栏**：① `g_last=false` ⇒ `L/TL` 显示 `—` 且不参与判定；② 任何状态下仍输出四栏实际番数（Q8）；③ 谓词只对结构听牌张定义，无听牌 ⇒ `未听牌（无和牌型）`，不得输出「不可和」。

**整手 vs 单张**：可和性**逐张**定义；整手存在非「不可和」的张即可给对应整手结论；**不得**把整手压成单一「条件」态。

**唯一性（含 v2.1 的表述纠正）**：
- **门清行**：`L=N+4`、`TL=T+4` 恒成立 ⇒ `N≥8 ⇒ L≥12`、`T≥8 ⇒ TL≥12` ⇒ 两世界一致，**无条件格**。
- **非门清 `base>0` 行**：`N=base`、`L=base+4` ⇒ `L=N+4` 成立；`T=base+1`、`TL=base+5` ⇒ `TL=T+4` 成立 ⇒ **无条件格**。
- **非门清 `base=0` 行**：`N=8` 是**无番和特判**抬升的，而 `L=4 = base+4` 无该特判 ⇒ **`L ≠ N+4`**。
  ⇒ **唯一条件格 = 非门清 + `base=0` + `g_last=true`**。
  > **纠正 v2.1 表述**：v2.1 曾写「`L=N+4`、`TL=T+4` 在门清与非门清下恒成立」——**对非门清 `base=0` 不成立**（L3-① 纠正 L2）；该例外正是条件格的成因。

### 3.2 不可和 / 条件可和 区间表（3 族 12 格 + 1 条件格）

| 情形 | `N` | `T` | `L` | `TL` |
|---|---|---|---|---|
| 门清 | `base+2` | `base+4` | `base+6` | `base+8` |
| 非门清（base>0） | `base` | `base+1` | `base+4` | `base+5` |
| **非门清且 base=0** | `8`（无番和，**仅点和**） | **`1`**（自摸不授予无番和） | **`4`（不得写成 12）** | **`5`** |

| 族 | 条件 | 结论 | 关键说明 |
|---|---|---|---|
| ① | 门清 + `¬g_last` | **不可和**（`base ∈ {0,1,2,3}`） | `concealed[t] ∈ {1,2,3}` |
| ② | 非门清 + `¬g_last` | **不可和**（`base ∈ {1,…,6}`） | `base=0` 见族④ |
| ③ | 非门清 + `g_last` | **不可和**（`base ∈ {1,2}`） | **已由 Lead 实测验证**：`78s 东东 --chi 234m --pon 5p --pon 6s` 的 `6条` 行 `base=2`（`四归一2`）⇒ `2/3/6/7` 全 <8、无 ✔ |

**恒可和（对照族，防修复「过度拒绝」）**：门清 + `g_last`（`TL=base+8≥8`）｜门清 + `¬g_last` + `base ≥ 4`｜**非门清 + base=0 + `g_last=false`**（`N=8`，仅点和）｜非门清 + `g_last` + `base ≥ 3`。

> **第二处单栏抬升（`T6-17`）**：`全求人`（`src/fans.rs:1017-1023`）也只在 `mode==Normal` 生效（`N += 6` 并删 `单钓将`）⇒ 4 副明副露 + 单钓的手在 `base=0` 时 `total = 6 ≠ 0` ⇒ **无番和反而不触发**（`N=6` 而非 8）。据此推导 `N=6 / T=1 / L=4 / TL=5`，**需实测确认**（→ §8 `U-11`）。

#### `M2` 逐项算式与三方冲突说明（**执行阶段首要裁定项**）

**当前实测（Lead 实跑，作为起点）**
```
$ cargo run --quiet --bin gbmj -- 147m 258s 369p 5p --kan 1p
5筒           14      15         —           —   ✔
5筒: 组合龙12 单钓将1 无字1
```
⇒ 当前 `base = 12 + 单钓将1 + 无字1 = 14`，`N = 14`（非门清 `N = base`），**`无字1` 已在当前实现中计入**，当前无 `明杠1`、无 `幺九刻1`。

**本方案（规则推导）`base` 逐项算式**
| 项 | 分值 | 计入理由 | 是否受 R-11 影响 |
|---|---|---|---|
| 组合龙 | 12 | 9 张针织牌成立 | 已实现 |
| **明杠** | **1** | `--kan 1p` 是**明杠**（`Meld::kan(tile, true)`），杠系番应由 R-11 补齐 | **R-11 新增** |
| **幺九刻** | **1** | 1筒是**幺九牌**，其**杠**按番种表应计幺九刻（`幺九刻` 含杠） | **R-11 新增** |
| 单钓将 | 1 | 和牌张 5筒 补将、且结构听牌仅 5筒 一张 | 已实现 |
| **无字** | **1** | 本手**无任何字牌**（9 针织 + 1筒 + 5筒将全是数牌）⇒ `无字` 成立；**当前实测也已计入** | 已实现 |
| — | — | **合计 `base = 16`**；`--kan` 是**明杠 ⇒ 破门清** ⇒ 非门清口径 `N = base = 16`、`T = base + 自摸1 = 17` | |

⇒ **本方案期望 `M2 = 16 / 17 / — / —`。**

**与开发方案 v2.1（`18/20`）的调和点**：`18 = 16 + 2`、`20 = 16 + 4`，**恰等于把 `base=16` 套「门清」公式（`N=base+2`、`T=base+4`）**。而 `--kan` 是**明杠**，依 `src/model.rs` 的 `breaks_menqing`（吃/碰/**明杠**破门清，仅**暗杠**不破）⇒ 应为**非门清**口径。
**故分歧很可能不在 `base`，而在门清判定**（18/20 使用了 `+2/+4`）。若开发方案的 `base` 确实是 16 而口径误用门清，则 `M2` 的正确值是 **16/17**；若开发方案的 `base` 实为 14 且另有 +4 来源，则需其给出逐项算式对齐。

**处理方式（Lead 指定）**：
> `M2` 列为**执行阶段首要裁定项**：**执行时先落原始输出，再比对期望**；若实际与纸面不符，按 **B1/B3 以规则推导为准**，并**升级 Lead/用户**，**不在纸面阶段继续互推**。

**关于 `无字1` 是否需要用户拍板（B2）**：**不需要新增拍板**——`无字` 的定义是「和牌中无字牌」，本手确实无字牌；且**升级 B 已裁决的 `M1 = 19/21` 本身就包含 `无字1`**（`12+暗杠2+幺九刻1+单钓将1+无字1+门清2 = 19`），即用户已隐含接受「组合龙与无字不互斥」。**唯一前提**：若用户认为组合龙不应计 `无字`，则 `M1/T1-09` 应为 18/20、`M2` 应为 15/16，需**整体重算**——此项已登记为 `U-18` 备查。

**结构性边界（不可达，务必写清）**
1. **`m ≥ 2`**：`src/calc.rs` 的 `detect_zuhelong` 开头 `if m > 1 { return out; }` ⇒ 组合龙只支持 `m ≤ 1`；「组合龙 × 双杠/三杠/四杠」**不可达**（设计边界，非缺陷）。
2. **m=0 且暗牌第 4 面子为暗杠**：`detect_zuhelong` 的 `m=0` 分支只生成 `Set::run` / `Set::triplet`（**不生成 kan**）⇒ 疑不可达，需实测（`U-14`）。
3. **多刻子类番不可达**：`双箭刻6`/`三风刻12`/`小四喜64`/`大四喜88`/`双同刻2`/`三同刻16`/`双明杠4`/`双暗杠6`/`一明一暗杠5`/`三杠32`/`四杠88` 均需 **≥2 副刻子/杠**，而组合龙分支只有**一副**第 4 面子、9 张针织牌均为数牌 ⇒ **不可达**（若报出即为 bug）。
4. **m=1 副露为杠**：`collect_special` 经 `ctx.melds[0].to_set()` 可取到 `is_kan=true` ⇒ 杠系番可达（R-11 修复落点）；但 `detect_zuhelong` 的 `m=1` 分支**只校验将、不校验面子形状**（`U-15`）。

**互斥尊重**：`无字` 在含任一字牌时**必然失效**（`collect_special` 判 `!has_honor`）；圈风刻/门风刻**可同推**（东=圈=门时 +2+2，两个独立 `if`），与 `幺九刻` 是 `else-if` 互斥；箭刻独立（`dragon_tri==1`）；「组合龙 + 箭刻 + 无字」**不可能同时成立**。
