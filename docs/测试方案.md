## 3. R-01 判定谓词（v2.3 · 测试方案确认版）

### 3.0 计分口径的三条硬前提

1. **四栏拆分**：`base` = 该和牌张分解下的**牌型番合计**（不含和法番）。门清：`N=base+2`、`T=base+4`、`L=base+6`、`TL=base+8`；非门清（`base>0`）：`N=base`、`T=base+1`、`L=base+4`、`TL=base+5`。
2. **无番和判定门 = `total == 0`，`total = base + extra`（extra 含和法番）**，且**只在 `mode == Normal`**。
   > **来源：Lead 读码**（`src/fans.rs:1004-1032`）。**非 L3 产出。**
   > 推论：绝张路径 `total = 4 ≠ 0` ⇒ **无番和永不适用于绝张** ⇒ **在「非门清 `base=0`」这条路径上，`L` 不可能等于 12**（该路径 `L = base + 4 = 4`）。
   > **⚠️ 适用范围限定（2026-10-12 修正，T14 实测反例）**：上句的「`L` 不可能等于 12」**仅在「非门清 `base=0` + 无番和特判」语境下成立**，**不是**对整个引擎的无条件断言。**反例（实测）**：`gbmj 222m 222s 345m 99m 67s`（门清，`base=8`：双暗刻2 + 双同刻2 + 缺一门1 + 无字1 + 门前清2）⇒ `N=8 / L=12`（`L = base + 6 = 12`，`can_last=true`）**完全合法**。⇒ **`L=12` 本身不是错误**；**真正的禁令**是「**不得出现 `无番和8 + 和绝张4 = 12` 的错误叠加**」（即不得让`无番和`的 +8 与`和绝张`的 +4 计入同一栏）。该禁令已由 §二十一 `T1-14A` 的名字级证据坐实（`fans_last` 恰含`和绝张4`、**不含**`无番和`）。
3. **自摸路径不授予无番和**（`mode != Normal` 直接排除）⇒ 非门清 `base=0` 时 **`T = base + 自摸1 = 1`**。
   > **来源：Lead 实测**（`78s 东东 --chi 234m --pon 5p --pon 6s` 的 `9条` 行自摸栏 = 1）。
   > **据此关闭 `U-13`**：`base` 在 `T/L/TL` 三栏均取**真实值 0**（`src/fans.rs:1025` 在 extra 并入前求和；无番和的 `total=8` 只写在 `Normal` 分支内），**该列不可能为 9**。**v2.0 的 `T=9` 推导已废弃**（错误原因：把仅点和授予的 +8 横移进了自摸栏再 +1）。

### 3.1 定义：两个世界 + 三态标注

对**结构听牌张** `t`，`concealed` = 未含和牌张的暗牌（`13 − 3n` 张）：

```
g_last(t) ⇔ (concealed[t] == 0)        ← 假设，不是事实（用户裁决）
```

**关键语义（升级 A）**：`g_last=true` 表示「**按绝张算给你看**」，**不否定非绝张世界**。因此：

```
非绝张世界可和(t) ⇔ N(t) ≥ 8 ∨ T(t) ≥ 8          （N/T 恒适用）
绝张世界可和(t)   ⇔ g_last(t) ∧ ( L(t) ≥ 8 ∨ TL(t) ≥ 8 )
可和(t)           ⇔ 非绝张世界可和 ∨ 绝张世界可和

三态（逐张 t）：
  「可和」                 ⇔ 非绝张世界可和 ∧ ( ¬g_last ∨ 绝张世界可和 )
  「条件可和（仅非绝张）」 ⇔ g_last ∧ 非绝张世界可和 ∧ ¬绝张世界可和
  「不可和」               ⇔ ¬非绝张世界可和 ∧ ( ¬g_last ∨ ¬绝张世界可和 )
```

**三护栏**：① `g_last=false` ⇒ `L/TL` 显示 `—` 且不参与判定；② 任何状态下仍输出四栏实际番数（Q8）；③ 谓词只对结构听牌张定义，无听牌 ⇒ `未听牌（无和牌型）`，不得输出「不可和」。

**整手 vs 单张**：可和性**逐张**定义；整手存在非「不可和」的张即可给对应整手结论；**不得**把整手压成单一「条件」态。

**唯一性（含 v2.1 的表述纠正）**：
- **门清行**：`L=N+4`、`TL=T+4` 恒成立 ⇒ `N≥8 ⇒ L≥12`、`T≥8 ⇒ TL≥12` ⇒ 两世界一致，**无条件格**。
- **非门清 `base>0` 行**：`N=base`、`L=base+4` ⇒ `L=N+4` 成立；`T=base+1`、`TL=base+5` ⇒ `TL=T+4` 成立 ⇒ **无条件格**。
- **非门清 `base=0` 行**：`N=8` 是**无番和特判**抬升的，而 `L=4 = base+4` 无该特判 ⇒ **`L ≠ N+4`**。
  ⇒ **唯一条件格 = 非门清 + `base=0` + `g_last=true`**。

### 3.4 展示层断言

> **★ 关键设计口径（用户 2026-10-12 裁定，后续 UI 相关一律以此为准）**：
> **GUI 的「状态标注」只用于异常态** —— 不可和 / 条件可和 / 仅自摸可和 / 仅绝张可和，会在**行尾输出整句标注并着色**（不可和＝灰 `120`；条件可和 / 仅自摸 / 仅绝张＝金 `200,160,60`）；
> **行尾既无标注、也无着色者即「可和」**。因此 **GUI 侧不给可和行补任何标记**（`✔` 是 **CLI** 的表示法，不适用于 GUI）。
> 依据：`src/bin/gbmj_gui.rs:462-482` —— 纯 `WinVerdict::Win`（且非仅自摸/仅绝张）时 `mark = ""`，**不输出任何标注**。
> **⚠️ 口径边界（勿混淆）**：这里的「换色」专指**行尾状态标注的颜色**，**不是**四个数值的颜色——数值着色是**另一套规则**（`gbmj_gui.rs:454-460`：`v >= 8` 显红 `235,90,80`、不足显灰 `120`），**可和行的数值本就会显红**，这不影响「无标注即可和」的判读。
> **推论**：`UI-02`/`UI-06` 中「`✔`」的表述**仅适用于 CLI**；GUI 侧的等价断言应改为「**可和行无状态标注、异常行有整句标注+着色**」。

1. **`m ≥ 2`**：`src/calc.rs` 的 `detect_zuhelong` 开头 `if m > 1 { return out; }` ⇒ 组合龙只支持 `m ≤ 1`；「组合龙 × 双杠/三杠/四杠」**不可达**（设计边界，非缺陷）。
2. **~~m=0 且暗牌第 4 面子为暗杠~~ → 范畴澄清（`U-14` 已关闭，2026-10-12 用户裁定）**：**`m` 是「副露数」**（`src/calc.rs:12` 注释；`let m = melds.len()`），**不是杠数**；且**杠必须声明为副露**（`--kan`/`--ankan` 才产生 `Meld`，暗牌里 4 张同牌**不构成杠**——实测 `1111m 222m 333m 44m 5m` 番表无任何杠番，只计「四归一」）。⇒ **`m=0` 即「零副露」⇒ 引擎模型中根本不存在杠**，故「m=0 时第 4 面子为暗杠」**是范畴错误**（把 `m` 误读为杠数才会问出），**既非缺陷、也不宜称"结构性不可达"**。原表述作废。
3. **多刻子类番不可达**：`双箭刻6`/`三风刻12`/`小四喜64`/`大四喜88`/`双同刻2`/`三同刻16`/`双明杠4`/`双暗杠6`/`一明一暗杠5`/`三杠32`/`四杠88` 均需 **≥2 副刻子/杠**，而组合龙分支只有**一副**第 4 面子、9 张针织牌均为数牌 ⇒ **不可达**（若报出即为 bug）。
4. **m=1 副露为第 4 面子：形状必须参与计番（`U-15` 已关闭，非缺陷，2026-10-12 用户裁定）**：`detect_zuhelong` 的 `m=1` 分支**只负责「找出将」**（`cc[p]==2`，`sets` 恒空），**第 4 面子的形状不在此处判定**——形状经 `ctx.melds[0].to_set()` **正确透传到计番层**，这正是正确设计：**第 4 面子能决定是否有`平和`，且它本身可能带番数**。实测同手同和牌张、仅换形状：
   | 第 4 面子 | 番数 | 番表 |
   |---|---|---|
   | `--chi 234m` | 15 | 组合龙12 + **平和2** + 单钓将1 |
   | `--chi 456m` | 15 | 组合龙12 + **平和2** + 单钓将1 |
   | `--pon 5p` | 14 | 组合龙12 + 单钓将1 + **无字1**（**无平和**） |
   ⇒ 碰子不给平和、吃子给平和，番数与番表随形状正确变化 ⇒ **「不校验形状」非缺陷**（校验发生在正确的层）。原「只校验将、不校验面子形状」的**疑点表述作废**。

**互斥尊重**：`无字` 在含任一字牌时**必然失效**（`collect_special` 判 `!has_honor`）；圈风刻/门风刻**可同推**（东=圈=门时 +2+2，两个独立 `if`），与 `幺九刻` 是 `else-if` 互斥；箭刻独立（`dragon_tri==1`）；「组合龙 + 箭刻 + 无字」**不可能同时成立**。
